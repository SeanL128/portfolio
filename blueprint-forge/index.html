Blueprint Forge

claude code plugin · three skills · markdown blueprints

Spend your most powerful model while you still have it on interviewing and blueprinting, so the cheaper models you'll still have next month can build it cold — at basically the same quality.

v1.3.0 · MIT · released

Why it exists

You can't trust that the powerful model you have today will still be there next week when you actually want to build — watching Claude Fable get pulled from the market made that concrete. Blueprint Forge spends the big model while you still have it on the part only it can do well: interviewing you about every ambiguity and writing self-contained blueprints. Those blueprints and their run-order ledger live in your repo, so any cheaper model you still have access to can execute them cold, as far into the future as you want, at basically the same quality — every decision was already made and written down.

The interview is the other half. Every autonomous run eventually hits an ambiguous spec and resolves it with a coin flip; in my blind benchmarks (20+ graded runs) the hard interview stop caught every planted ambiguity (8/8 runs), while plain sessions asked zero questions and advisory gates self-waived under autonomous dispatch (5/5).

The honest caveat: blueprints are easily invalidated by a pivot. Use the split path only when the project's direction is certain and the decisions are made — all that's left is the building. If that's not true yet, use blueprint-oneshot for the one task in front of you, or settle the direction in a separate session first and blueprint after.

Or send Claude the repo and have it install the skills. First run bootstraps a blueprints/ folder in your repo with a MODELS.md routing map and a RUN-ORDER.md ledger.

The skills

Two ways in. All are user-invoked only — Claude never triggers them on its own, because they deliberately spend premium planning-model tokens.

  • blueprint-oneshot One task end to end: interview → blueprint → your approval → autonomous build + review. Two hard stops, then hands-off. oneshot
  • blueprint-backlog Turn a backlog/TODO into blueprints — approve, revise, or reject each — plus a run-order ledger where every item assumes the state the previous ones leave behind. split · 1
  • blueprint-implement Build one approved blueprint: dispatch its builder subagents, review the result against it, route ship / fix here / re-dispatch / re-blueprint. split · 2

Model routing

Blueprints name roles, never model IDs. blueprints/MODELS.md maps each role to a model for the harness in play — the default is a Claude split, and an optional per-role dispatch command column can send builds to another harness entirely. The split I run daily: Claude blueprints and reviews, GPT-5.6 builders via Codex CLI — building burns most of the tokens, so a separate $20 ChatGPT subscription absorbs them and Claude usage limits barely move. The worked map ships in the repo's README.

How it works

A blueprint is a self-contained markdown file written for a builder that starts cold, works alone, and cannot ask questions — if a fact isn't in the file or the repo, it doesn't exist for the builder. Each carries its builder role, grounding references, dependencies, starting state, a definition-of-done checklist, and reviewer notes. The ledger tracks a closed status vocabulary, and an item is only checked off once review passes — which makes the whole plan resumable across sessions, days, or models.

Every skill was built test-first against blind baseline runs (watching what context-free agents do wrong without the skill, then gating exactly that), and the suite was benchmarked across 20+ graded runs on toy and ~350-file repos before release.

What I learned / what broke

Advisory process gates don't survive autonomy. Every suite I tested that recommends asking questions waived its own gate the moment it ran headless — five out of five. Only a hard stop-and-wait held, and building that took writing skills test-first against blind baseline runs rather than writing rules and hoping.

Blind graders penalize negotiated answers. The resolution the user actually chose in an interview can grade worse than the guess a judge would have made — the suite's value shows up in variance, not means, which changed how I position it: insurance, not a quality upgrade.

The economics only work with routing. Pinned to one premium model the pipeline costs 3–4× a plain session; arbitraging build tokens to cheaper builders cut the premium to 1.5×.
